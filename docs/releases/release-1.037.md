# v1.037 —「锁」撤了

**一句话**：v1.035 起界面上那些压暗、标着「锁」、点一下只弹「要官方解锁」的集，现在点下去直接出 1080P。

## 那道锁是怎么来的

`GET /api/v1/series/detail?series_id=<id>` 里，core 会给出两个字段：

- `accessible_episode_cnt`：本机（走 core 取流）能看到的集数，这部 48 集的剧是 `3`
- `episodes[i].locked`：第 4 集之后全部 `true`（core 内部的 `locked_inferred`，推断值）

v1.035 据此做了 UI 拦截：格子压暗 + 右上角一个「锁」、集数行写「共 48 集 · 前 3 集公开」、点集弹 toast、自动接集到锁集就停、悬停预取跳过锁集。

**但这只是网页端的口径。** `locked` 表达的是「core 取流和官网页兜底拿不到」，不代表 App 侧拿不到。

## 实测：它其实是开着的

1080P 走的是 `helper/` 里那套 App 侧签名取流，根本不看 `locked` 这个字段。同一部剧（48 集，`accessible_episode_cnt=3`）抽样实测：

| 集 | 选择 | 结果 | 大小 | 耗时 |
|---|---|---|---|---|
| 4 | 1080p | ok | 4,077,207 B（1080×1924） | 1134 ms |
| 10 | 1080p | ok | 4,739,325 B（1080×1924） | 1115 ms |
| 20 | 1080p | ok | 3,060,740 B（1080×1924） | 817 ms |
| 30 | 1080p | ok | 4,197,116 B（1080×1924） | 986 ms |
| 40 | 1080p | ok | 2,019,558 B（1080×1924） | 558 ms |
| 48 | 1080p | ok | 4,235,146 B（1080×1924） | 1573 ms |

第 4 集是 v1.035 里被标成「锁」的那一集，也是当初实测出 `no_public_source` 的那一集。

## 这版删了什么

- 分集格子的压暗样式与右上角「锁」字（`ui/index.html` 里 `.ep[data-lock="1"]` 三条规则一并移除）
- 点集时的拦截与 toast（`#sEps` 的容器级 click 委托里那段 `dataset.lock` 判断）
- `playEpisode` 顶部的锁集拦截 —— 自动接集 / 右侧队列不会再「到锁集就停」
- 悬停预取里「锁集别预取」的跳过
- 集数行的「· 前 3 集公开」

现在点哪一集都直接进 `playEpisode` → `loadStream`（1080P 优先）。

## 不是把提示删掉假装能播

`giveUp` 里那条兜底文案照旧存在，只是把预设口径改掉：

- 旧：`core 的取流接口对所有剧都返空，官网页那条兜底接口也没给出这一集的片源（no_public_source）。官方把这集锁着（本机免费到第 3 集）`
- 新：`1080P 助手、core、官网页三条路都没给出这一集的片源（<why>）`

也就是说：真取不到的时候，仍然是走完三条路之后才报，并且不再拿「官方锁着」当解释。`S.locked` / `S.lockN` / `S.freeN` 这几个变量留着只做日志参考，不再参与任何判断。

## 已知边界

- `locked` 是 core 给的推断值，本来就没逐集穷举过；这版反过来验证了抽样 6 集（含被标锁的第 4 集）全部可取。没抽到的集若真取不到，界面照实报「三条路都没片源」，不会假装在播。
- `helper/` 那 150 MB 大头是 Python 运行时 + ffmpeg；ffmpeg 只在本机放不了 HEVC 时才用得上。
- 每集成品是 `%TEMP%\hgplay-*` 的临时文件，下次开始播放时自动清掉上一轮。
