# v1.036（2026-11-26）

一句话：**真 1080P 回来了 —— 点一集就取官方原片、本机解密后直接播，拿不到再自动退回 360P。**

## 问题是什么

从 11-22 起，core 走的那套 App 取流接口对所有剧、所有画质都返 HTTP 200 + 0 字节（core 日志里的 `VIDEO_MODEL_EMPTY`）。当时能用的只有官网页给普通访问者留的那条兜底，它只给一档 360P。这不是登录态问题，也不是地区问题，是官方那侧换了实现。

## 这版怎么绕开的

`helper/` 是一个独立的小服务，自带 Python 运行时，在本机把官方 App 的签名流程完整跑一遍，拿到真实的多档播放地址（360p / 480p / 540p / 720p / 1080p 一次全给），再把 `cenc-aes-ctr` 加密的片子解成明文。外壳只做两件事：

```
/hgplay?vid=<vid>&q=1080p&t=0    取流 → 下载 → 解密（t=1 时再转码）
/hgfile?p=<本地 mp4>             把成品带 Range 转发给 <video>，拖进度条能跳
```

两个端点都只听 `127.0.0.1`，端口由系统分配、通过 `&wport=` 告诉前端，不对外暴露。

## 能播 HEVC 就不转码

先用 `canPlayType` 探本机能不能放 H.265：

- 能放 → 不转，解密后的原片直接交出去。一集约 5 MB，单集 1~3 秒。
- 放不了 → `loadedmetadata` 后没起来或直接 error，回头请求 `t=1` 转成通用 H.264。慢十几秒，但任何机器都能播。

实测同一集：不转码 `5,289,793 B`（1080×1924，89.235s），转码 `26,059,547 B`（h264 1080×1924，2140 帧全部可解）。

## 不会卡在转圈

- `helper/` 不存在 → 一次都不试，直接走老路。
- 这一集取不到、或助手超时 → 静默退回，并在 `HDBAD` 里记一笔，下次不再多等一轮。
- 播不出来（HEVC 放不动）→ 不是放弃，是换转码再来一次；两次都不成才退回 360P。

## 启动就把初始化做掉

助手的 SDK 会话（设备身份 + SDK 镜像 + token）要十几秒，界面一起来就后台 `warm`，点播放时只剩取流这一下。会话常驻后实测**第一集 1 秒、第二集 2 秒**，强制转码 12 秒。

## 顺手的两个小事

- 选集格子右上角出现绿色 `HD`：只标本机确实取到过高清的集，没取到过的空着 —— 不提前许诺。
- 每集成品是 `%TEMP%\hgplay-*` 里的临时文件，下次启动自动清掉上一轮留下的。

## 两个包

| 包 | 体积 | 说明 |
|---|---|---|
| `hongguo-skin-1.036-win64.zip` | 6,999,888 B | 只有 360P 兜底，和以前一样 |
| `hongguo-skin-1.036-win64-hd.zip` | 65,911,924 B | 多带 `helper/`（约 150 MB），能取真 1080P |

高清版把 `helper/` 整个删掉，就是轻量版；轻量版把 `helper/` 拷进去，就是高清版。两者共用同一份 `%APPDATA%\HonggoDesktop` 数据，不冲突。
