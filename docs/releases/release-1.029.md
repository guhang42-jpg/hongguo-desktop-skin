# v1.029 — v1.028 那一版的自查修复（8 处）

v1.028 把四道约束塞进语义检索之后，回头把这块从头到尾又审了一遍。下面每一条都是真实会碰上的，不是理论风险。

## 改了什么

**1. 推理没有互斥 —— 补串行锁**

搜索框连着敲，`top()` 会被连发好几次；小果那边意图判定和检索也会前后脚撞上。同一个 wasm 会话并发 `run()` 不是安全的：轻则结果错乱，重则直接抛错。v1.028 加的「超时」还会让问题更明显 —— 超时只是调用方不等了，底层那次 run 仍在跑。

- 新增 `encQ(text)`：所有推理过一条 `lock` 队列，同一时刻只允许一条 run；`lock` 用 `.catch` 兜住，失败不会把后面的堵死
- `reset()` 里把 `lock` 重置，免得一条卡死的 run 把新推理永远挡在后面

**2. 体检行被省略号吃掉**

`.row .mono` 有 `max-width:230px` + `nowrap` + `ellipsis`，而体检那一行是 `模型 22.8MB · 指纹 一致 · 线程 1 · 加载 1.2s · 单句 38ms · 库内 1130 部` —— 230px 装不下，后半截直接变成「…」。

- 新增 `.row .mono.wide{max-width:none;white-space:normal;line-height:1.55}`，体检行用它，允许折两行，不再截断

**3. 打开设置永远是「未加载」**

模型只在被用到时才加载，用户点开设置·本机大概率看到「未加载」，还以为这版没生效。

- 进入「本机」页时静默 `boot()` 一次，状态自己从「加载中 · 读模型」走到「就绪」
- 加载中每 1.2s 重绘这一页（`setTick`），读完再刷一次，不用手动重新打开
- 只在这一页触发；轻量版没带 ai 目录，会走 404 → 标「本机版没装模型」，不报错

**4. 加载失败后每次搜索都重读 22MB**

`boot()` 失败会把 `pending` 置空，于是下一次 `top()` 又从头走一遍整链 —— 连续搜几次就是反复读 22.8MB 模型。

- 失败后记 `st.errAt`，30 秒内直接返回上次的失败状态，不再重试；「重载」按钮会清掉这个时间戳，想立刻重试照样能试

**5. 状态复位不全**

`boot()` 只清了 `err`，`fp` / `missing` / `it` / `encMs` 会带着上一次的值进下一轮，体检行可能短暂显示旧的「指纹 一致」。

- `boot()` 开头清 `fp / missing / it / encMs / errAt`；`reset()` 再清 `mb / loadMs`，重载时体检行如实显示「—」直到新数字出来

**6. 「重载」按钮不管成败都说「已重新加载」**

- 改成按结果说话：成功 → 「模型已重新加载」；轻量版 → 「这个版本没带模型」；失败 → 「没加载起来：<原因前 22 字>」

**7. 超时文案会写出「0s」**

`within()` 里 `(ms / 1000).toFixed(0)`，120ms 这种会变成「0s」。

- 改成 ≥1000ms 走秒（`8s` / `22s`），不足 1 秒写毫秒（`120ms`）

**8. 分组顺序**

「语义检索」原本排在「数据」前面，一进本机组先看到模型状态、看不到数据目录在哪。改成先「数据」、再「语义检索」、最后「清理」。

## 已知边界

- 串行锁是排队不是抢占：前一条 run 卡住时，后一条要等它跑完或等到自己的超时，所以极端情况下单句会比 8 秒更晚出结果（会直接退回关键词，不会卡界面）
- 30 秒冷却对「文件刚修好」这种场景不友好，需要点一次「重载」才立刻重试
- 进设置·本机会预载模型（约 22.8MB 读盘 + 建会话），语义版用户本来就要用，轻量版会 404 后静默跳过
- 只动 `ui\app.js`、`ui\index.html`、`ui\version.txt`、`ui\build.txt`；外壳 exe、core、播放链路未碰

## 安装

下载对应压缩包，解压到任意目录，双击 `红果短剧.exe`。首启会在 `%APPDATA%\HonggoDesktop` 起本地数据目录；保留旧目录即为升级。语义版多带 10 个模型文件，放 `ui\ai\` 下，小果会自己用。
