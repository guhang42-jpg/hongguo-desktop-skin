# v1.028 — 语义检索补上四道工程约束：门槛、指纹、超时、体检行

这版没有新功能，也没动皮肤。改的是 `ui\app.js` 里那块本机语义检索（bge-small-zh int8 + onnxruntime-web）的工程卫生 —— 参考 ImageToolbox 那套 AI 模块的做法，把四件原本靠运气的事变成有约束的流程。

## 为什么改

原来这段加载是「一把梭」：fetch 全部资源 → 建会话 → 直接用。中间任何一步慢、坏、或者机器本来就带不动，界面只会一直转圈，或者静默返回空结果，而且没有任何地方能看出它到底在干什么。

## 改了什么

**1. 门槛：内存不到 4GB 就降级，不硬撑**

- 读 `navigator.deviceMemory`，小于 4GB 进降级档：单句推理超时从 8 秒收到 5 秒，体检行标黄显示「低内存 · 已降级」
- 拿不到这个值（部分 WebView2 版本不暴露）就按正常档跑，不误判
- 不禁用、不弹窗，只是把等待上限收紧一点

**2. 指纹：模型对不上就不加载**

- 新增 `ui\ai\manifest.json`，记 `model.onnx` / `vectors.bin` / `vocab.txt` / `index.json` / `intents.bin` 的字节数与 SHA-256
- 加载时用 `crypto.subtle.digest` 算一遍 `model.onnx` 的 SHA-256，和清单比对，不一致直接抛错、拒绝建会话
- 为什么值这一步：坏掉的 onnx 不会报错，它会正常建起会话，然后每次推理都吐 NaN —— 语义检索变成永远返回空，界面上没有任何提示。指纹把「静默错误」变成「明确失败」
- 清单不存在时（比如旧包）跳过校验，不因此拒载

**3. 超时：每一步都有上限，卡住就退回关键词**

- 读清单 4s / 读模型 15s / 建会话 12s / 整链兜底 22s
- 单句推理 8s（降级档 5s），超时返回空数组或 null；上层 `findSem` 本来就有 `.catch`，自然退回关键词检索
- 超时次数累积进体检行，一次运行内可查

**4. 体检行：设置·本机里一眼看到它活着没、跑多快**

设置面板「本机」组新增「语义检索」一栏，三行：

- **模型状态**：就绪（绿）/ 加载中 · 读模型（灰）/ 本机版没装模型（灰）/ 指纹不符（红）/ 低内存 · 已降级（黄）
- **体检**：`模型 22.8MB · 指纹 一致 · 线程 1 · 加载 1.2s · 单句 38ms · 库内 1130 部`
- **超时次数**：只有出现过超时才显示，避免正常时多一行噪音
- 一行动作「重载」：清旧会话，重新走一遍含指纹校验的完整流程

## 已知边界

- 指纹校验让语义版首次加载多花约 100–200ms（22.8MB 的 SHA-256），之后就只走缓存会话
- 门槛依赖 `navigator.deviceMemory`；WebView2 不提供该值时按正常档，不做降级
- 单句超时不自动重试，本句直接退回关键词结果
- 只动 `ui\app.js`、`ui\index.html`，新增 `ui\ai\manifest.json`；外壳 `红果短剧.exe`、本地 core、播放链路一律未碰

## 安装

下载对应压缩包，解压到任意目录，双击 `红果短剧.exe`。首启会在 `%APPDATA%\HonggoDesktop` 起本地数据目录；保留旧目录即为升级。语义版多带 10 个模型文件，放 `ui\ai\` 下，小果会自己用。
