### 形态

- 「我的」正下方一颗 52px 圆球，外圈一道慢呼吸的光环。光环是纯 CSS 的 transform + opacity，走合成层，CPU 不参与
- 点开是一卷**从球往上长出来**的气泡，344 宽、圆角 20、毛玻璃底，跟现有那套灵动岛一个语言
- 气泡底边贴着球的顶部；窗口矮了自动压高度，不会顶到窗口外面被裁掉（第一版就是这里溢出，截图才发现）
- 全屏播放、小窗模式下不出现——侧栏那时本来就不在，别让气泡浮在画面上
- 关掉再开，上一轮的对话还在；`Esc` 也能收

### 它能干的（全部走 core 的本地接口）

| 你说 | 它做的 |
|---|---|
| 我上次看到哪了 | 翻追剧记录，报剧名 / 第几集 / 全几集 / 还剩几集 / 多久前看的，附一张「接着看」卡 |
| 有没有修仙的、找部爽的 | 剥掉"有没有""找"这类虚词，剩下关键词走 `lists/search`，点卡片直接开详情 |
| 推荐点啥、无聊 | 走 `lists/recommend`，把你追剧记录里已有的剔掉 |
| 找部短的、一晚上刷完 | 按集数筛。这池子里没有 20 集以内的，它会直说，不硬凑 |
| 看《XX》 | 搜到就直接往下播第 1 集 |
| 我收藏了啥 | 收藏夹按时间排，最近两部 |
| 看了几部 | 追剧记录部数 / 有续播点的部数 / 最近一次看的时间 |
| 你能干啥 | 能力清单，顺带把边界讲清 |

### 为什么第一版不做大模型

参照 `T8RIN/ImageToolbox` 的路子：它那套 AI Assistant 也不是塞了个通用大模型——答案死锁在 App 自己的 Help & Tips 里，模型按需下载、ONNX 端侧跑、用完就卸；相册语义搜索也是本地小 embedding 建的索引。

红果这边更省事：**core 已经把剧库摆在你面前了**（推荐 / 搜索 / 详情 / 追剧台账 / 收藏）。缺的从来不是"生成能力"，是"把结构化数据说成人话"。所以这版就是规则 + 模板：

- 意图靠 10 条正则加词表打分，不调模型，判断耗时为 0
- 回答靠模板拼，里面每个数字都来自 core 的真实响应
- 常驻开销就是一段 JS：没有定时器、没有轮询，气泡关着的时候连 DOM 都不动

真要"能顺着你追问两句"的版本，再挂 L1.5（`bge-small-zh` 25MB，意图 + 语义检索，单次 <50ms）和 L2（Qwen2.5-0.5B Q4，可选下载、闲置自动卸载）。这版先不塞。

### 说清边界

- 它只说剧库里有的。问"今天天气"它会讲接不住，不会编
- core 给的字段只有标题 / 标签 / 简介 / 评分 / 集数 / 类型，**没有 BE·HE、甜度这类标签**，所以"别推虐的"做不到
- 统计只报能对上的三项。**不报"总时长"**——`position` 只是"这一集的续播点"，把 1124 部加起来会得出"看了 19686 集、一共 11 小时"这种一眼假的数，第一版就踩了，已经删掉
- 推荐池是一次 24 部的快照，不是全库。"最短的也有 124 集"是实话，不是没努力
- 它不会替你下单、不会改你的账号设置，只读数据
